# 디자인 피드백 반영안 v2

작성일: 2026-07-04

## 1. 폰트 후보

앱에 외부 CDN 없이 번들링할 수 있고, 상업적 사용과 재배포가 가능한 오픈 폰트만 후보로 둔다.

추천 순서:

1. SUIT
   - UI 본문용으로 만든 한글 폰트라 버튼, 작은 라벨, 결과 숫자가 비교적 단정하다.
   - 라이선스: SIL Open Font License.
   - 출처: https://github.com/sun-typeface/SUIT

2. Pretendard
   - 국내 웹/앱에서 많이 쓰이는 무난한 기본값이다.
   - 라이선스: SIL Open Font License.
   - 출처: https://github.com/orioncactus/pretendard

보류 후보:

- Noto Sans KR: 안정적이지만 앱 인상이 다소 기본 브라우저처럼 보일 수 있다.
- IBM Plex Sans KR: 완성도는 높지만 마작 계산기 UI에는 약간 사무 도구 인상이 강하다.

Wanted Sans로 확정한다.

## 2. 패 이미지

B2로 확정한다.

- FluffyStuff의 공개 도메인 타일 심볼을 기반으로 한다.
- 원본 타일 이미지를 그대로 쓰지 않고, 앱용 타일 몸체를 다시 렌더링한다.
- 내부 여백을 늘리고, 녹색 측면과 그림자를 넣어 흰 배경과 구분한다.
- 37종 전체 패를 전부 이미지 버튼으로 노출한다.
- 적5만, 적5통, 적5삭은 일반 5와 별도 버튼으로 둔다.

출처:

- FluffyStuff riichi-mahjong-tiles: https://github.com/FluffyStuff/riichi-mahjong-tiles

## 3. 입력 구조 수정

확정 반영:

- 장풍과 자풍은 론/쯔모 옆에 끼우지 않는다.
- 장풍, 자풍은 각각 독립된 동/남/서/북 선택지로 둔다.
- 패 선택 영역에는 37종 전체를 항상 보여준다.
- 몸통/머리 후보는 처음부터 임의 표시하지 않는다.
- 사용자가 특정 패를 고르면, 그 패를 포함할 수 있는 후보만 보여준다.
- 후보 영역의 후로 여부는 버튼이 아니라 체크박스 1개로 둔다.
- 머리 후보에는 후로 체크박스를 붙이지 않는다.
- 화료패와 후보 패 표시는 모두 이미지 패로 한다.

## 4. 깡 직후 및 도라/우라 입력

확정 반영:

- “마지막 깡 직후에 화료했나요?”는 도라/우라 입력 직전에 묻는다.
- 선택지 순서는 “예 / 아니오”다.
- 사용자가 “예”를 고른 경우, 앱이 기존 입력값으로 마지막 깡도라/깡우라도라 인정 여부를 판단한다.
- 깡이 2개 이상이고 암깡/명깡이 섞여 있어 마지막 깡 판정이 달라지는 경우에만 추가 질문을 띄운다.
- 추가 질문이 뜬 경우, 답변 후 판정 결과 문구를 보여준다.

판정 문구:

- 리치/더블리치가 없을 때 인정: “해당 깡으로 인한 도라는 인정됩니다. 포함하여 입력해주세요.”
- 리치/더블리치가 없을 때 미인정: “해당 깡으로 인한 도라는 인정되지 않습니다. 제외하고 입력해주세요.”
- 리치/더블리치가 있을 때 인정: “해당 깡으로 인한 도라와 우라도라는 인정됩니다. 포함하여 입력해주세요.”
- 리치/더블리치가 있을 때 미인정: “해당 깡으로 인한 도라와 우라도라는 인정되지 않습니다. 제외하고 입력해주세요.”

도라/우라 입력 UI:

- 도라 표시패는 5개 빈칸을 먼저 보여준다.
- 우라 표시패도 리치/더블리치일 때 5개 빈칸을 보여준다.
- 각 칸을 누르면 패 선택 팝오버가 열린다.
- 도라/우라 안내 문구에서는 “이번 화료에 적용되는” 표현을 쓰지 않는다.
- 기본 문구는 “도라 표시패를 순서대로 모두 입력하세요.”로 둔다.
- 리치/더블리치일 때는 “도라 표시패와 우라 표시패를 순서대로 모두 입력하세요.”로 둔다.

## 5. 역/결과 표시

확정 반영:

- 결과의 역 목록은 선택 버튼처럼 보이면 안 된다.
- `리치` 등 역 이름은 중립적인 태그로 표시한다.
- 도라와 깡도라와 적도라는 `도라 N`으로 합산한다.
- 우라도라는 `우라도라 N`으로 별도 표시한다.
- 판수 동점 후보가 있으면 기본 결과 하나만 보여주고, 표시 위에 hover 또는 탭 팝오버로 후보 목록을 보여준다.
- 팝오버가 열린 상태에서 다른 곳을 클릭하면 닫는다.

## 6. 레퍼런스 기반 UI 방향

화면 자체, 브랜드 에셋, 스크린샷은 복제하지 않는다. 공개 디자인 시스템의 원칙만 참고한다.

후보:

1. Material 3 방향
   - 모바일 터치, 선택 상태, 큰 결과 카드에 유리하다.
   - 이 앱처럼 “빠르게 누르고 바로 결과 확인”하는 흐름에 가장 맞다.
   - 출처: https://m3.material.io/

2. Radix Themes 방향
   - 담백하고 장식이 적다.
   - 계산 도구처럼 보이는 장점이 있지만, 모바일 첫인상은 약간 평범할 수 있다.
   - 출처: https://www.radix-ui.com/

3. Carbon 방향
   - 데이터 도구 느낌이 강하고 정보 밀도 관리가 좋다.
   - 단점은 다소 사무용 툴처럼 보일 수 있다는 점이다.
   - 출처: https://carbondesignsystem.com/

현재 추천은 Material 3 계열 레이아웃 + SUIT + B2 타일이다. 사용자가 이전 시안의 3번째처럼 밝은 앱형을 선호한다면, Material 3 방향이 가장 자연스럽다.
