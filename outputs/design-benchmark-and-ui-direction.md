# 디자인 벤치마크 및 UI 방향

작성일: 2026-07-04

## 1. 디자인 원칙

이 앱은 랜딩 페이지가 아니라 실사용 계산 도구다.

따라서 첫 화면은 설명용 히어로가 아니라 계산 입력 화면이어야 한다.

핵심 원칙:

- 모바일 한 손 조작 우선
- 결과는 즉시 읽혀야 함
- 패 버튼은 작탁 조명 아래에서도 구분되어야 함
- 입력 단계는 길어도 각 단계가 명확해야 함
- 장식보다 정보 밀도와 터치 정확도를 우선
- 카드 남용 금지
- 색상은 작혼풍을 직접 복제하지 않고, 차분한 도구형 팔레트 사용

## 2. 벤치마크 후보

### 2.1 Riichi Calculator

참고 요소:

- 상단에 현재 손패가 먼저 보이는 구조
- Chi/Pon/Kan/Ankan 같은 행위 버튼이 큼
- 타일 그리드가 한 화면에서 빠르게 선택 가능
- 흰 배경과 강한 타일 대비

주의점:

- MVP에서는 Chi/Pon/Pon 같은 호출 종류를 직접 받지 않는다.
- 후로 여부만 받는다.
- 버튼을 너무 많이 한 줄에 넣으면 한국어 라벨이 터질 수 있다.

### 2.2 Riichi Calc / Riichi Mahjong Calculator

참고 요소:

- 계산 결과가 점수/역/부수로 명확히 분리된다.
- 결과 화면에서 패와 점수를 함께 보여준다.
- 부수 breakdown이 계산 신뢰도를 높인다.

주의점:

- 데스크톱/태블릿 느낌의 여백을 그대로 가져오면 모바일에서 입력이 느려진다.
- MVP는 결과보다 입력 속도가 더 중요하다.

### 2.3 Mahjong Soul

참고 요소:

- 패 정렬 순서: 만/통/삭/자패
- 패 가독성
- 숫자 보조 표기

주의점:

- 작혼 UI/이미지를 복제하지 않는다.
- 분위기나 캐릭터성보다 계산기 도구성을 우선한다.

## 3. 화면 구조

### 3.1 전체 레이아웃

모바일 폭 기준:

1. 상단 상태 바
   - 현재 입력 진행률
   - 새로 입력/공유/기록 버튼
2. 조건 입력 영역
   - 론/쯔모
   - 장풍/자풍
   - 본장/공탁
   - 상황역
3. 손패 영역
   - 현재 입력된 완성형 패
   - 고정 후로/암깡 표시
   - 화료패 표시
4. 패 선택 그리드
   - 37종
   - 선택 불가 패는 비활성화
5. 후보 패널
   - 선택한 패로 만들 수 있는 머리/순자/커쯔/깡쯔
   - 몸통에는 후로 체크박스
6. 도라/우라 표시패 입력
   - 도라 입력 전에 마지막 깡 직후 화료 여부를 확인
7. 결과 영역

### 3.2 입력 단계의 시각 우선순위

가장 눈에 띄어야 하는 것:

- 현재 완성형 패
- 다음에 해야 할 행동
- 계산 결과

덜 눈에 띄어야 하는 것:

- 도움말
- 공유/기록
- 세부 breakdown

## 4. 컴포넌트 기준

### 4.1 패 버튼

- 터치 영역 최소 44px
- 실제 타일 이미지는 34~40px 폭
- 아래에 짧은 텍스트 라벨 표시
- 적도라는 빨간 5와 일반 5가 명확히 구분되어야 함
- 이미 4장 사용된 패는 비활성화
- 적5는 각 색 1장 사용 후 비활성화

### 4.2 선택지 버튼

론/쯔모, 장풍/자풍은 토글 스위치가 아니라 선택지 버튼으로 둔다.

마지막 깡 직후 화료 여부는 도라/우라 표시패 입력 단계에서 선택지 버튼으로 묻는다.

선택지 버튼 요구사항:

- 선택 상태가 명확해야 함
- 선택되지 않은 버튼도 터치 가능하게 보여야 함
- 긴 텍스트는 2줄 허용

### 4.3 상황역 버튼

- 리치/더블리치/일발/해저/하저/영상/창깡
- 선택 불가 조합은 비활성화
- 비활성 이유는 탭하면 짧게 표시

### 4.4 후로 체크박스

몸통/머리 후보에서 후로 여부는 버튼이 아니라 체크박스로 둔다.

- 후보 선택 버튼과 후로 체크박스를 분리한다.
- 머리 후보에는 체크박스를 표시하지 않는다.
- 깡쯔 후보에서 체크 해제는 암깡, 체크는 명깡으로 해석한다.

### 4.5 결과 카드

카드는 결과 요약 하나에만 사용한다.

반복되는 작은 정보는 카드 안에 또 카드로 넣지 않는다.

결과 우선순위:

1. 점수
2. 판수/부수 또는 등급
3. 역 목록
4. 도라/우라도라 개수
5. breakdown

## 5. 색상 방향

금지:

- 작혼과 혼동될 정도의 직접적인 브랜드 팔레트
- 과한 보라/파랑 그라데이션
- 지나친 베이지/갈색 일색
- 어두운 슬레이트 일색

추천 방향:

- 배경: 밝은 회색 또는 아주 옅은 녹색기 있는 흰색
- 주요 액션: 진한 청록 또는 먹색
- 선택 상태: 선명한 녹색/청록
- 경고: 주황/적색
- 패 영역: 흰색 타일 + 얇은 회색 경계

색상은 최종 구현 전 벤치마크 시안에서 승인받는다.

## 6. 타이포그래피

- 모바일 기본 16px 이상
- 버튼 라벨 12~14px
- 결과 점수 28~36px
- 긴 역 이름은 줄바꿈 허용
- viewport 폭에 따라 폰트 크기를 직접 스케일하지 않는다.
- letter-spacing은 0

## 7. 패 이미지 후보

### 후보 A: 사진풍 자체 생성

장점:

- 실제 패 느낌
- 작탁 사용 맥락에 잘 맞음

단점:

- 작은 크기에서 숫자/문자가 흔들릴 수 있음
- 모든 37종을 일관되게 만들기 어려움

### 후보 B: 오픈 라이선스 타일

장점:

- 정확도 높음
- 전체 세트 확장이 쉬움
- 라이선스만 지키면 배포 가능

단점:

- 개성이 적음
- 원본 라이선스 표기 필요

### 후보 C: 직접 제작한 깔끔한 타일

장점:

- 앱 톤에 맞게 통제 가능
- 작은 크기에서 가독성 좋음
- 라이선스 리스크 최소

단점:

- 실제 패 느낌은 약함
- 제작 품질을 직접 검수해야 함

## 8. 승인 전 확인할 시각 요소

구현 전에 사용자에게 보여줄 것:

- 패 이미지 후보 3종
- 모바일 첫 화면 와이어프레임
- 결과 화면 와이어프레임
- 색상 팔레트 2~3개

사용자가 선택/수정한 뒤 실제 MVP 구현에 들어간다.
