# 리치마작 부수계산 앱 상세 리뷰 후속 기록

검토 기준: 390px 모바일 렌더링, 계산/공유/최근기록 코드, 공유 링크 복원, 브라우저 콘솔, 정적 검증.

## 선조치한 명백한 오류

1. 공유 링크가 완성 계산이어도 2페이지 손패 입력으로 열리던 문제를 수정했다.
   - 변경: `src/app.js`의 초기/해시 복원 단계에서 상태 완성도에 따라 1/2/3/4페이지를 결정하도록 변경.
   - 확인: 완성된 공유 URL을 새로 열면 결과 페이지로 진입.

2. 공유 해시 디코더에 길이 제한이 없던 방어 취약점을 보강했다.
   - 변경: `src/domain.js`에 최대 4096자 제한 추가.
   - 확인: 과도하게 긴 공유 payload 거부 테스트 추가.

3. 특정 상황역에서 검증은 오류로 잡지만 1페이지 버튼으로는 선택 가능하던 조합을 막았다.
   - 대상: `영상개화+해저로월`, `창깡+하저로어`, `영상개화+일발`, `창깡+더블리치`.
   - 변경: 버튼 노출 조건과 상태 정규화 양쪽에서 정리.
   - 확인: 쯔모+리치+일발 상태에서 `영상개화`가 숨겨지고, 론+더블리치 상태에서 `창깡`이 숨겨짐.

## 검증 결과

- `node --test tests/domain.test.js`: 35개 통과.
- `node scripts/verify-static-app.js`: 통과.
- 브라우저 콘솔 error/warning: 없음.
- 390px 모바일 렌더링:
  - 1페이지, 2페이지 37종 패 선택, 3페이지 도라/우라 입력, 결과, 최근계산, 공유, 동점 해석 모달에서 가로 넘침 없음.
  - 패 이미지는 `assets/tiles/b2`에서 로드되며 누락 없음.
  - 3판 70부 만관은 `3판 70부 / 만관`으로 표시됨.
  - 만관 이상 최근계산은 부수 없이 `N판`으로 표시됨.
  - 공유 링크 샘플 길이: 74자.

## 사용자 응답 반영

1. 결과 카드의 만관 이상 표시를 `9판 / 배만`처럼 최종 판수와 limit명을 함께 표시하도록 변경했다.

2. `panel(title, note, children)`의 `note` 인자는 실제 화면에 렌더링되지 않았고, 현재 앱 방향상 짧은 계산 도구에 불필요한 설명을 늘릴 필요가 없어 제거했다.

3. `progress()`, `stepper()`, `shortTile()` 및 관련 CSS는 현재 UI에서 사용되지 않아 제거했다.

4. 공유 링크로 열린 완성 계산도 결과 페이지 진입 시 최근계산에 자동 저장되는 현재 동작은 유지한다.

5. 비리치 상태에서는 우라도라 표시패 영역을 아예 숨기도록 변경했다.

6. 같은 슌쯔 4개도 량페코로 판정되도록 변경했다.
   - 작혼 공식 교실은 량페코를 이페코 2개로 설명한다.
   - 일반 리치마작 자료에서도 같은 슌쯔 4개는 이페코 2개로 해석 가능한 경우 량페코 성립으로 본다.

## 남은 확인 필요

1. 결과/모달 일부 항목은 시각적으로는 그리드 간격이 있지만 DOM 텍스트만 보면 `지불8000`, `배만리치 1판`처럼 붙어서 읽힌다.
   - 화면 사용에는 문제 없어 보이나 접근성까지 보려면 aria-label 또는 공백 텍스트를 따로 줄 수 있다.
