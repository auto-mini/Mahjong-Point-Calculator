## 리뷰 001: 계산 엔진과 테스트 범위

관점:

- 계산 도메인 모델 명확성
- 대표 케이스 테스트 누락
- 상황역 상충 처리
- URL fragment/localStorage 안전성

발견:

- 론 샤보로 완성한 커쯔가 삼암각에 잘못 포함될 수 있었다.
- 화료패가 최종 손패에 없는 상태, 일발 단독 선택, 일부 상황역 상충 검증이 부족했다.
- 공유 링크 파싱이 allowlist 스키마로 제한되지 않았다.
- 최근계산 복원 데이터가 계산 가능 상태인지 재검증되지 않았다.
- 대표 테스트가 8개로 목표 문서의 핵심 케이스 일부만 덮고 있었다.

조치:

- 론으로 완성한 커쯔를 삼암각 암각 카운트에서 제외했다.
- 화료패 부재, 일발 단독, 해당없음 동시 선택, 영상개화/해저/창깡/하저 등 상충 검증을 보강했다.
- 공유 payload를 allowlist 방식으로 정규화하도록 `sanitizeStatePayload`를 추가했다.
- 최근계산 항목을 `sanitizeRecentItems`로 재검증한 뒤 노출/복원하도록 바꿨다.
- 대표 테스트를 20개로 확장했다.

## 리뷰 002: 모바일 390px 레이아웃

관점:

- 390px 화면 깨짐
- 하단 CTA와 콘텐츠 겹침
- 결과 페이지 스크롤 부담

발견:

- 고정 footer가 1페이지의 상황역 버튼 일부를 덮었다.
- DOM 폭은 정상이어도 실제 캡처에서 버튼 영역이 콘텐츠를 침범했다.

조치:

- footer를 fixed/sticky 오버레이에서 정적 흐름 배치로 변경했다.
- 390px 재검증에서 가로 오버플로와 주요 요소 겹침이 0건임을 확인했다.

## 리뷰 003: 공유/최근계산 흐름

관점:

- URL fragment 생성/복원
- 최근계산 저장/복원
- 공유 링크 파싱 실패 UI

발견:

- 개발 서버가 캐시 헤더를 주지 않아 브라우저 QA 중 수정 전 모듈이 남아 공유 복원 확인을 방해했다.

조치:

- 개발 서버 응답에 `cache-control: no-store`를 추가했다.
- 공유 fragment로 완성 손패를 복원한 뒤 결과 페이지 이동, 최근계산 모달, 최근 항목 복원, 공유 모달, 잘못된 fragment 오류 표시를 검증했다.

## 리뷰 004: 상세 설계서 역/역만 누락

- 치또이형 혼노두가 일반역 목록에 포함되지 않았다.

조치:

- 치또이 손패가 모두 요구패일 때 혼노두를 함께 판정하도록 보강했다.

## 리뷰 005: 상세 검증 규칙 누락

관점:

- 표시패까지 포함한 수량 초과 검증
- 창깡 상황역의 MVP 제한

발견:

- 손패 4장 + 도라/우라 표시패 1장으로 같은 물리 패가 5장 이상 보이는 경우를 잡지 못했다.
- 창깡이 순자 대기에서만 가능한 MVP 제한을 검증하지 않았다.

조치:

- 손패, 도라 표시패, 우라도라 표시패를 합친 visible tile 수량을 재검증했다.
- 창깡 선택 시 가능한 화료형 중 화료패가 순자를 완성할 수 없으면 계산 불가 오류를 내도록 했다.
- 관련 테스트 2개를 추가해 총 24개 도메인 테스트가 통과하도록 했다.

## 잔여 제한

- 역만은 목표 문서대로 점수 계산하지 않고 감지 시 중단한다.
- 국사무쌍 입력/점수 계산은 비목표라 제외했다.
- 마지막 깡 직후 추가 질문은 창깡/영상개화/론 직전 깡도라 규칙에 맞춰 분기한다.
- 패는 FluffyStuff public-domain 타일 심볼을 바탕으로 만든 로컬 B2 PNG 타일로 표시한다.
