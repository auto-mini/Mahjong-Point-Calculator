# 리치마작 부수계산 웹앱 와이어프레임 목표

## 목적

리치마작 부수계산 웹앱의 MVP 구현 전에 사용할 1~4페이지 모바일 와이어프레임을 최대한 완성도 높게 만든다.

이번 작업 범위는 앱 구현이 아니라 와이어프레임, 화면 설계, 상태 설계, 문구 설계, 시각 밀도 조정이다. 실제 계산 로직 구현, 프론트엔드 앱 구현, 배포, 백엔드 작업은 하지 않는다.

## 고정 기준

- 기준 화면 폭: iPhone 14/15 계열 390px 폭.
- 폰트: Wanted Sans.
- 패 스타일: B2 타일.
- 전체 디자인 톤: I Wallet Stack 기반.
- 배경: G처럼 연한 웜 그라데이션.
- 구역: K처럼 바깥 배경보다 진한 패널로 분리.
- 결과 카드: 붉은 카드 중심.
- 보조 카드/프레임: 딥그린 계열.
- G의 지저분한 선 장식은 사용하지 않는다.
- K의 장난감 같은 강한 노랑/토이 감성은 피한다.
- 전체 산출물은 모바일 우선으로 설계한다.

## 산출물

필수 산출물:

- 1~4페이지 PNG 와이어프레임.
- 페이지별 설명 MD.
- 상태 전환과 입력 흐름 설명 MD.
- 자체 리뷰 기록 MD.

필요하면 추가 산출물:

- 간단한 HTML 미리보기.
- 컴포넌트별 상세 확대 PNG.
- 오류 상태/팝오버/최근계산 모달 별도 PNG.

100번 리뷰 동안 개선할 것이 없을 경우 추가 산출물:

- 확정 시안 기반 미세 조정 변형 20종 PNG.
- 변형 비교 MD.
- 변형은 기능/플로우 변경 없이 박스 간격, 카드 높이, 여백, 버튼 크기, 섹션 간격만 다르게 한다.

## 공통 내비게이션

- 1페이지에는 뒤로가기 없음.
- 2~4페이지 좌상단에는 뒤로가기 버튼.
- 2~4페이지 우상단에는 최근계산 버튼.
- 최하단 확인 버튼은 페이지별 필수 입력이 완료되어야 활성화된다.
- 확인 버튼은 화면 하단에서 찾기 쉬워야 한다.
- 모바일 한 손 사용을 고려해 주요 진행 버튼은 하단에 둔다.

## 1페이지: 화료/국 정보

최상단:

- 론 / 쯔모 선택지.
- 기본 선택 없음.
- 둘 중 하나를 선택해야 확인 버튼 활성 조건을 만족한다.

그 아래:

- 장풍: 동 / 남 / 서 / 북.
- 자풍: 동 / 남 / 서 / 북.
- 본장: 기본 0본장.
- 공탁: 기본 0공탁.
- 장풍 기본값: 동.
- 자풍 기본값: 동.
- 장풍/자풍은 라디오 버튼 또는 드롭다운 중 모바일에서 더 명확한 방식으로 설계한다.
- 본장/공탁은 스텝퍼 또는 작은 숫자 입력 컨트롤로 설계한다.

그 아래 특정 상황역:

- 리치.
- 더블리치.
- 일발.
- 창깡.
- 영상개화.
- 해저모월.
- 하저로어.
- 해당없음.

상황역 규칙:

- 기본은 해당없음 선택.
- 해당없음을 누르면 나머지 상황역은 모두 해제된다.
- 다른 상황역을 누르면 해당없음은 해제된다.
- 리치와 더블리치는 동시에 선택될 수 없다.
- 일발은 리치 또는 더블리치가 있을 때만 유효하다.
- 해저모월과 하저로어는 동시에 선택될 수 없다.
- 창깡과 영상개화는 동시에 선택될 수 없다.
- 나머지 중복 여부는 리치마작 규칙에 맞게 자연스럽게 제한한다.

1페이지 확인 버튼:

- 론/쯔모가 선택되어 있어야 활성화.
- 장풍/자풍/본장/공탁은 기본값이 있으므로 별도 입력 없이 유효.
- 상황역은 기본 해당없음이 있으므로 별도 입력 없이 유효.

## 2페이지: 손패 입력

상단:

- 현재 손패 영역.
- 손패가 늘어나고 줄어듦에 따라 박스 높이가 유동적으로 바뀐다.
- 추가된 멘쯔/또이쯔는 각 세트를 구성하는 패 사이 간격을 좁게 표시한다.
- 각 세트는 연한 박스로 묶어 연결성을 나타낸다.
- 각 세트 박스 우상단에는 작은 X 버튼을 둔다.
- X 버튼을 누르면 해당 세트가 제거된다.
- 제거 후 14장 미만이 되면 패 선택 영역이 다시 나타난다.

화료패 영역:

- 현재 손패 구성이 완성된 뒤에 노출한다.
- 표준형은 몸통 4개 + 머리 1개 기준.
- 치또이는 머리 7개 기준.
- 깡은 4장으로 표시하되 완성 조건에서는 몸통 1개로 계산한다.
- 화료패 후보는 현재 손패 안의 중복 제거된 패로 제시한다.
- 적도라는 일반 5와 구분한다.
- 같은 패가 여러 장 있으면 맨 앞에 있는 패 1개만 후보로 보여준다.
- 화료패 선택 후 현재 손패 영역에서 해당 패 1개만 강조 표시한다.

패 선택 영역:

- 처음에는 37종 패를 모두 이미지로 보여준다.
- 37종: 만수 1~9, 통수 1~9, 삭수 1~9, 적5만, 적5통, 적5삭, 동, 남, 서, 북, 백, 발, 중.
- 처음 상태에서는 박스 크기가 크다.
- 패 하나를 선택하면 패 선택창은 선택한 패 1개만 보이는 작은 상태로 줄어든다.
- 선택한 패를 다시 클릭하면 선택이 취소된다.
- 선택이 취소되면 37종 전체가 다시 보인다.
- 선택이 취소되면 후보군 박스는 사라진다.
- 손패 구성이 완성되면 패 선택 박스는 사라진다.
- 세트 삭제나 초기화로 손패가 미완성이 되면 패 선택 박스는 다시 나타난다.

후보군 영역:

- 패 선택 영역에서 패 하나를 선택했을 때만 나타난다.
- 선택한 패를 포함하는 후보만 보여준다.
- 후보 종류: 머리, 슌쯔, 커쯔, 깡쯔.
- 머리/슌쯔/커쯔/깡쯔는 층으로 구분하여 표시한다.
- 후보 세트도 현재 손패의 세트 표시와 같은 방식으로 묶어서 표시한다.
- 적5가 포함된 후보와 일반 5가 포함된 후보는 다른 후보로 본다.
- 후보군 박스 높이는 후보 수에 따라 유동적으로 조절한다.

후보 선택 동작:

- 후보 1개를 선택하면 나머지 후보가 사라진다.
- 선택된 후보만 강조 표시로 남는다.
- 선택된 후보 아래 또는 옆에 `후로여부` 라벨을 보여준다.
- `후로여부` 라벨 아래에 `O` / `X` 버튼을 보여준다.
- `O` 또는 `X`를 누르면 즉시 현재 손패에 등록된다.
- 머리는 후로여부 없이 선택 즉시 등록된다.
- 선택된 후보를 다시 누르면 선택이 해제되고 기존 후보 전체가 다시 나타난다.
- 등록 후 후보군 박스는 사라지고 패 선택 영역은 37종 전체 상태로 돌아간다.

하단:

- 전체 초기화 버튼.
- 2페이지 확인 버튼.

2페이지 확인 버튼:

- 손패 구성이 완성되어야 활성화.
- 화료패가 선택되어 있어야 활성화.

## 3페이지: 도라/우라/깡 직후 판정

상단 순서:

1. `마지막 깡 직후에 화료했나요?` 질문.
2. 예 / 아니오 선택.
3. 필요하면 추가 질문.
4. 판정 문구 출력.
5. 도라 표시패 입력.
6. 우라도라 표시패 입력.

마지막 깡 질문:

- 예 / 아니오 순서로 표시한다.
- 기본 선택 없음.
- 이 질문에 응답해야 확인 버튼 활성 조건을 만족한다.
- 앱이 이미 알고 있는 화료 방식, 상황역, 손패의 깡 정보, 후로/안깡 정보를 바탕으로 마지막 깡도라/우라도라 인정 여부를 판단한다.
- 깡이 2개 이상이고 안깡과 안깡 아닌 깡이 섞여 있어 판단이 필요한 경우에만 추가 질문을 낸다.
- 추가 질문이 필요한 경우, 추가 질문에 답한 뒤 판정 문구를 보여준다.

판정 문구:

- 리치/더블리치가 없으면 도라만 언급한다.
- 리치/더블리치가 있으면 도라와 우라도라를 언급한다.
- 인정되는 경우: `해당 깡으로 인한 도라는 인정됩니다. 포함하여 입력해주세요.`
- 인정되지 않는 경우: `해당 깡으로 인한 도라는 인정되지 않습니다. 제외하고 입력해주세요.`
- 리치/더블리치가 있는 경우 문구는 `도라와 우라도라`로 바꾼다.

도라 표시패:

- 도라 표시패 5칸.
- 입력 전에는 빈칸 + 상태.
- 첫 칸은 필수.
- 칸을 누르면 34종 표시패 선택 UI가 열린다.
- 34종은 일반 1~9 만/통/삭 + 동남서북백발중.
- 적5는 표시패에서 별도 타입으로 다루지 않는다.
- 표시패 하나를 누르면 곧바로 해당 칸에 등록된다.
- 등록된 칸을 다시 누르면 해당 칸 입력이 취소된다.
- 후반 칸이 비어 있는 것은 없는 것으로 자동 처리한다.
- 중간 칸이 비어 있으면 경고를 표시한다.

우라도라 표시패:

- 우라도라 표시패 5칸.
- 리치 또는 더블리치가 없으면 비활성 처리한다.
- 리치 또는 더블리치가 있으면 활성화한다.
- 우라 활성화 시 우라도라 개수는 도라 표시패 개수와 같아야 한다.
- 개수가 맞지 않으면 경고를 표시한다.
- 입력 방식은 도라 표시패와 동일하다.

3페이지 확인 버튼:

- 도라 표시패 첫 칸이 입력되어 있어야 활성화.
- 마지막 깡 직후 질문에 응답해야 활성화.
- 중간 칸 누락이 없어야 활성화.
- 리치/더블리치가 있으면 우라도라 개수가 도라 개수와 같아야 활성화.

## 4페이지: 결과

상단:

- 결과 영역.
- 계산 불가 시 `계산 불가`와 이유를 명확히 표시한다.
- 정상 계산 시 작혼 결과 화면처럼 핵심 결과를 빠르게 읽을 수 있게 한다.

역 목록:

- 역 이름과 판수를 줄마다 표시한다.
- 도라는 `도라 N`으로 표시한다.
- 우라도라는 `우라도라 N`으로 표시한다.
- 깡도라, 적도라는 별도 줄로 표시하지 않고 도라에 합산한다.
- 역패는 `동`, `남`, `서`, `북`, `백`, `발`, `중`처럼 실제 패 이름만 표시한다.
- 장풍과 자풍이 같은 경우 `더블동`, `더블남`, `더블서`, `더블북`처럼 표시한다.
- 후로 감산이 있어도 `후로 혼일색`처럼 표시하지 않고 `혼일색`으로 표시한다.
- 판수 동점 후보가 있으면 표시 옆에 아이콘을 두고, 탭하면 후보 목록 팝오버를 보여준다.

부수 breakdown:

- 기본부.
- 멘젠 론.
- 쯔모부.
- 대기부.
- 머리부.
- 커쯔/깡쯔 부수.
- 특수형: 치또이 25부, 핑후쯔모 20부, 핑후론 30부 등.
- 최종 올림: 예시 `32부 -> 40부`.
- 만관 이상에서는 부수 breakdown을 숨기거나 축약한다.

최종 결과:

- 최종 몇 판 몇 부.
- 만관 이상이면 만관/하네만/배만/삼배만/카조에역만 등급.
- 총점수.
- 누구에게 얼마씩 가져올지 표시.
- 론은 방총자 1명 지불.
- 쯔모는 친/자 지불액을 구분한다.
- 본장/공탁 반영 표시.

하단:

- 공유.
- 다시 계산.
- 다시 계산은 전체 초기화 후 1페이지로 이동한다.
- 일부 수정은 뒤로가기로 처리한다.

## 최근계산

- 2~4페이지 우상단에 최근계산 버튼.
- 최근계산은 전체 화면 모달 또는 하단 시트로 설계한다.
- 최근계산 항목을 누르면 1~3페이지 입력값을 복원한다.
- 복원 후 일단 4페이지로 이동한다.
- 4페이지에서 뒤로가기로 수정 가능해야 한다.
- 최근계산은 최대 20개 기준으로 설계한다.

## 공유

- 4페이지 하단에 공유 버튼.
- 공유 링크를 만들 수 있는 흐름을 와이어프레임에 표현한다.
- 백엔드 없이 URL fragment 기반 공유를 전제로 한다.

## 팝오버/툴팁

- 모바일 기준: 탭해서 열기.
- 화면의 다른 곳을 탭하면 닫기.
- PC에서는 hover도 추가 가능하지만 모바일 탭 동작을 우선한다.
- 부수 항목 설명, 판수 동점 후보, 오류 상세 설명에 사용한다.
- 팝오버가 화면 밖으로 나가지 않도록 배치한다.

## 오류 상태

와이어프레임에 최소한 아래 오류 상태를 반영한다.

- 론/쯔모 미선택.
- 손패 미완성.
- 화료패 미선택.
- 동일패 5장 이상.
- 동일 수패 적5 2장 이상.
- 화료 형태 불가.
- 도라 첫 칸 누락.
- 도라 중간 칸 누락.
- 우라도라 개수 불일치.
- 도라만 있고 일반 역 없음.
- 역만 형태 감지 시 부수 계산 대상 아님.

## 리뷰 기준

각 리뷰마다 아래 관점으로 전체를 본다.

- 입력 플로우 누락.
- 사용자가 헷갈릴 지점.
- 모바일 한 손 사용성.
- 버튼/박스 간격.
- 카드 높이와 스크롤 부담.
- 상태 전환 누락.
- 오류 표시 위치.
- 도라/깡 질문 순서.
- 최근계산 동작.
- 공유 동작.
- 뒤로가기 동작.
- 팝오버 닫힘.
- 시각적 완성도.
- 디자인 톤 일관성.
- 1~4페이지 사이 정보 흐름.

## 작업 루프

1. 첫 와이어프레임 제작.
2. 커밋.
3. 전체 리뷰.
4. 개선할 점이 있으면 수정.
5. 실제 diff가 있으면 커밋.
6. diff가 없으면 커밋하지 않고 무개선 리뷰 카운트를 올린다.
7. 반복한다.

빈 커밋, 커밋을 만들기 위한 의미 없는 변경, 불필요한 포맷 변경 커밋은 금지한다.

## 중단조건

아래 중 하나에 해당할 때만 중단한다.

- 사용자가 중지를 지시한다.
- 작업 시간이 10시간을 초과한다.
- 100번 리뷰 동안 개선할 것이 없다.

100번 리뷰 동안 개선할 것이 없으면 즉시 종료하지 말고, 확정 시안을 기준으로 미세 조정 변형 20종을 추가 생성한다.

## 100번 무개선 후 미세 조정 변형 20종

변형 대상:

- 박스 간격.
- 카드 높이.
- 섹션 간 여백.
- 버튼 크기.
- 하단 확인 버튼 위치.
- 현재 손패 영역 밀도.
- 후보군 영역 밀도.
- 도라/우라 슬롯 간격.

변형 금지:

- 기능 변경.
- 플로우 변경.
- 정보 구조 변경.
- 색상 큰 변경.
- 폰트 변경.
- 타일 스타일 변경.

20종을 생성한 뒤 비교 MD를 작성하고 실제 파일 변경이 있으므로 커밋한다.

## 권장 GOAL 문구

`docs/wireframe-goal.md`의 지시를 기준으로, 리치마작 부수계산 웹앱의 MVP 구현 전 모바일 와이어프레임을 최대한 완성도 높게 만든다. 앱 구현은 하지 않는다. 산출물 생성, 자체 리뷰, 개선, 실제 diff가 있을 때만 커밋하는 루프를 사용자가 중지하거나 10시간을 넘기거나 100번 리뷰 동안 개선할 것이 없을 때까지 반복한다. 100번 무개선 조건에 도달하면 해당 문서의 지시에 따라 미세 조정 변형 20종을 추가 생성한다.
