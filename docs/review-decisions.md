# Review Decisions

이 문서는 전체 리뷰를 반복할 때 이미 검토했고 의도적으로 유지하기로 한 항목을 재지적하지 않기 위한 기록이다.
명백한 버그, 계산 오류, 보안 문제, 접근성 문제는 이 문서와 관계없이 다시 보고한다.

## 유지하기로 한 항목

### 도라 표시패 초과 입력 허용

도라 표시패가 실제보다 많이 입력되었는지는 앱이 확정할 수 없다.
깡 이력 전체를 입력받지 않기 때문이다.
따라서 도라 표시패 부족 입력은 막지만, 초과 입력은 허용한다.

다시 다룰 조건:
도라 표시패가 필요한 최소 개수보다 적은데도 계산되는 경우, 중간 빈칸이 있는데 통과되는 경우, 도라/우라 개수 규칙이 깨지는 경우.

### 하단 버튼 스크롤 허용

하단 버튼이 레이아웃 밖으로 깨지거나 입력 영역에 가려지는 것이 아니라, 스크롤로 접근 가능한 상태라면 허용한다.
모바일 입력 흐름에서는 고정 footer가 하단 콘텐츠를 가릴 수 있으므로 현재 구조를 유지한다.

다시 다룰 조건:
버튼이 화면 밖으로 렌더링되어 스크롤로도 접근할 수 없는 경우, 다른 요소에 가려져 터치할 수 없는 경우, 버튼 때문에 입력 내용이 잘리는 경우.

### 과거 공유 링크 호환성 낮은 우선순위

향후 공유 링크 포맷이 바뀌면서 과거 링크가 깨져도 허용한다.
개인 사용 버전에서는 구버전 호환성보다 구현 단순성과 현재 동작의 정확성을 우선한다.

다시 다룰 조건:
현재 버전에서 새로 생성한 공유 링크가 복원되지 않는 경우, 잘못된 링크가 앱을 깨뜨리는 경우, 악성 입력 방어가 약해지는 경우.

### 공탁 미지원

공탁금은 앱 입력/공유/결과 표시에서 제외한다.
현재 앱의 목적은 부수와 기본 점수 확인이며, 공탁은 사용자가 별도로 더해 가져가는 것으로 본다.
따라서 UI 상태에서 `riichiSticks`를 0으로 고정하는 것은 의도된 정책이다.

다시 다룰 조건:
공탁 입력 UI를 다시 추가하기로 결정한 경우, 공탁 0인 일반 계산에 영향을 주는 경우.

### 역만 제외

국사무쌍뿐 아니라 천화/지화 등 역만 화료는 앱 계산 대상에서 제외한다.
역만을 알고 있는 사용자는 부수계산 앱을 사용할 필요가 없다는 전제다.

다시 다룰 조건:
역만을 결과 화면에서 명시적으로 차단하거나 안내하기로 정책을 바꾸는 경우, 일반 비역만 손패가 역만으로 오탐되어 계산이 막히는 경우.

### O/X 후로 선택 화면 표시 유지

후로 여부 선택은 현재의 O/X 버튼 표시를 유지한다.
화면상 라벨을 더 길게 늘리지 않는다.
단, 접근성 라벨이나 내부 설명은 필요하면 유지해도 된다.

다시 다룰 조건:
O/X 터치 영역이 너무 작아 조작이 어려운 경우, 어느 쪽이 후로인지 앱 내부 라벨이나 접근성 정보에서도 구분되지 않는 경우.

### 지불 표시 형식 유지

현재의 간단한 지불 표시 형식을 유지한다.
불필요하게 긴 설명이나 표 형태로 바꾸지 않는다.

다시 다룰 조건:
점수 계산이 틀린 경우, 론/쯔모/오야/자별 지불 금액이 잘못 표시되는 경우, 표시 형식 때문에 금액을 오해할 수 있는 경우.

### 결과 상단 총점 표시 유지

결과 상단의 큰 점수는 총점으로 표시하고, 실제 지불액은 지불 영역에 따로 표시한다.
쯔모 결과에서도 상단은 합산 총점, 지불 영역은 `400 / 800` 또는 `12000 all` 같은 지불액 형식으로 둔다.

다시 다룰 조건:
사용자가 상단 큰 점수를 지불액 중심으로 바꾸기로 결정한 경우, 총점과 지불액 중 하나가 계산상 틀린 경우.

### 보조글자 대비 조정 유지

작은 보조 라벨과 안내문 색상은 현재처럼 약간 더 진하게 유지한다.
주요 제목, 점수, 결과 정보의 디자인 변화가 아니라 작은 글자의 가독성 보정이다.

다시 다룰 조건:
대비가 접근성 기준을 명확히 밑도는 경우, 보조글자가 배경과 구분되지 않는 경우, 전체 톤이 의도와 다르게 무거워지는 경우.

### 본장 입력은 0~8로 제한

이 앱은 초보자끼리 실제 작탁에서 부수와 기본 점수를 빠르게 확인하는 용도다.
9본장 이상은 현실적인 사용 빈도가 매우 낮고, 화면에 추가 입력 장치를 두는 비용이 더 크다고 판단해 지원하지 않는다.
따라서 UI의 0~8 버튼과 도메인의 8본장 상한은 의도된 제품 범위로 유지한다.

다시 다룰 조건:
9본장 이상 계산 요청이 실제 사용에서 반복되는 경우, 숫자 입력이나 증감 버튼을 추가하기로 결정한 경우, 0~8 범위의 점수 계산이 틀리는 경우.

### 버튼 확대 모드 크기 기준

버튼 확대 모드는 일반 조작 버튼의 최소 한 변을 42px, 5열 패 격자와 세트 삭제 같은 밀집형 조작의 최소 한 변을 40px로 둔다.
결과의 부수 펼침 버튼과 `body`에 렌더링되는 모달 조작도 확대 범위에 포함한다.
기본 모드는 WCAG 2.5.8의 24px 최소 타깃 기준을 지킨다.

다시 다룰 조건:
320px에서 가로 스크롤이나 조작 영역 겹침이 생기는 경우, 확대 모드 조작이 위 기준보다 작아지는 경우, 더 큰 44px 이상 기준으로 바꾸기로 결정한 경우.

## 리뷰 시 참고

- 위 항목은 같은 이유로 반복 지적하지 않는다.
- 위 항목이라도 실제 화면 깨짐, 계산 오류, 보안 문제, 접근성 실패가 확인되면 다시 보고한다.
- 새로 결정한 보류/기각 항목이 생기면 이 문서에 추가한다.
