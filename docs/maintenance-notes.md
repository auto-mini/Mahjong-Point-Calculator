# Maintenance Notes

이 문서는 당장 해결할 문제는 아니지만, 이후 수정 과정에서 쉽게 잊으면 안 되는 주의점을 남긴다.

## 계산 정확도

- 가장 큰 리스크는 UI보다 계산 오류다.
- 특히 창깡, 영상개화, 일발, 리치, 우라도라, 깡도라가 함께 얽히는 경우는 수정 때마다 주의한다.
- 계산 로직을 바꾸면 대표 케이스를 테스트에 추가하고, 기존 86개 테스트가 모두 통과하는지 확인한다.

## 모바일 환경

- 실제 목적은 작탁에서 휴대폰으로 빠르게 확인하는 것이다.
- 작은 화면, 큰 글자 설정, iOS Safari, Android Chrome에서 버튼/패/알림 문구가 겹치지 않는지 확인한다.
- 새 UI를 추가하면 320px급 폭에서 한 번은 확인한다.

## 공유 링크

- 공유 링크는 현재 입력값을 복원하기 위한 편의 기능이다.
- 앱 상태 구조가 바뀌면 과거 링크가 깨질 수 있으며, 현재 정책상 과거 링크 호환은 최우선 목표가 아니다.
- 과거 링크 보존이 필요해지면 share state 버전 변환 코드를 별도로 설계한다.

## 의도적으로 제외한 기능

- 역만 손패, 국사무쌍, 공탁금, 유국만관은 계산 대상에서 제외한다.
- 이 기능들을 아는 사용자는 보통 부수계산기가 필요하지 않다는 전제다.
- 제외 정책을 바꾸려면 입력 흐름, 결과 표시, 테스트 범위를 함께 재검토한다.

## 최근계산 저장

- 최근계산은 현재 브라우저의 localStorage에만 저장된다.
- 기기 변경, 브라우저 데이터 삭제, 시크릿 모드에서는 사라질 수 있다.
- 서버 저장 기능을 추가하지 않는 한 중요한 기록 보관 기능처럼 안내하면 안 된다.

## 줄바꿈과 문구

- 앱 전체에 한글 줄바꿈 규칙을 적용했다.
- 새 버튼이나 짧은 라벨을 추가할 때 의도치 않은 줄바꿈이 생길 수 있다.
- 긴 알림 문구는 글자 단위로 쪼개지지 않는지 확인한다.

## 배포

- 현재 배포는 `main` push 후 GitHub Actions가 테스트, 빌드, Pages artifact 배포를 수행한다.
- 예전 `gh-pages` 브랜치 강제 푸시 방식은 더 이상 사용하지 않는다.
- 배포가 실패하면 먼저 `Deploy static site` workflow의 Test, Build, Upload artifact, Deploy 단계 중 어디서 실패했는지 구분한다.

## 정리 정책

- `dist/`는 빌드 산출물이므로 커밋하지 않는다.
- 디자인 시안, 생성 스크립트, 대용량 참고 폰트/타일 원본은 운영에 필요하지 않다.
- 유지해야 할 것은 실제 앱 코드, 테스트, 배포 workflow, 최종 검증 기록, 리뷰 결정 기록이다.
